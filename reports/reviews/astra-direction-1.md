**프로젝트를 유지하면서 B의 범위를 좁혀 구현하고, A2를 실문서 외부 평가로 붙이는 조합을 추천합니다.** 공고와 직접 연결되는 품번·수량·단가·표 추출을 유지하면서, 합성 데이터에서 배운 개선이 실제 사진에도 전달되는지 보여줄 수 있습니다.

다만 **0.994는 깨끗한 자체 dev 20건의 결과**입니다. 프로젝트 전체가 너무 쉽다는 결론까지 확대하면 안 됩니다. 기존에도 모호수량·누락행 실패가 남았습니다([정밀도 비교](../../reports/quant/precision_dev20.md#L6), [실패 분석](../../reports/eval/dev_summary.md#L42)).

**1. 추천 범위**

B에서는 **7–12행, 여러 줄 품명, 포장수량 표현, 한영 혼합 헤더, 사람이 읽을 수 있는 촬영 왜곡**부터 추가하세요. SKU 정답과 독립 PO를 유지할 수 있어 직무 적합성이 높습니다. 기존 32건 보강이 효과 없었으므로, 단순 증량보다 실패 구조를 다양하게 만드는 것이 중요합니다([보강 결과](../../reports/eval/dev_summary.md#L48)).

15–40행·다페이지·유럽식 숫자·3자 대사는 다음 단계로 미루겠습니다. 현재 대사는 **최대 12행**, 생성 한도는 **1,536토큰**이라 동시에 확장하면 모델 성능과 시스템 제한이 섞입니다([대사 제한](../../src/invoiceguard/reconciliation.py#L16), [토큰 예산](../../src/invoiceguard/vlm/sft.py#L18)).

A2는 직접 라벨링 부담이 있지만 영어 표 문서라는 연결성이 좋습니다. 제공하신 라이선스 조사 기준으로 CORD보다 목적에 가깝습니다. CORD는 라벨 확보가 쉬운 대안이지만 인도네시아 영수증이라는 차이가 큽니다. DocILE은 장기적으로 가장 매력적이나 접근·허가 일정 때문에 이번 완료 조건에서 제외하세요. C로의 전환은 수일 안에 데이터 정리와 제품 구현을 모두 끝내기 어렵습니다.

**2. 평가 설계**

| 세트 | 권장 구성·역할 |
|---|---|
| 어려운 합성 train | 약 400–600개 독립 거래, 기존 clean 데이터 일부 혼합 |
| 합성 dev | 약 80–100개, 난이도·학습 설정 선택 |
| 신규 합성 held-out | 최소 100개 독립 거래, 미학습 레이아웃과 미학습 변형 조합 |
| A2 실문서 | 개발용 약 20개, 봉인 평가용 최소 60개·목표 100개 |
| 기존 FINAL | 과거 결과로 보존, 새 모델 선택에 사용하지 않음 |

같은 거래의 clean/열화본은 반드시 같은 split에 넣고, 실문서는 중복·발행처·템플릿 관계로 분리하세요. 발행처가 하나라면 일반화 주장도 그 범위로 제한해야 합니다. 실문서의 없는 SKU·단가를 추정해 정답으로 만들지 마세요.

사전에 다음을 고정하겠습니다.

- **주 비교:** M0 BF16 대 M1 BF16 LoRA. QLoRA는 NF4 M0와도 비교하고, 실용적 경쟁 상대인 M0 BF16도 함께 보고.
- **주 지표:** SKU·품명·수량·단가의 필드별 정확도와 사전 정의한 평균. 코드펜스 제거를 양쪽에 동일 적용한 내용 정확도와 strict JSON 성공률을 분리.
- **성공 기준 예시:** 신규 합성 held-out에서 **+3%p 이상**, 문서/family 단위 paired bootstrap **95% CI 하한 >0**. seed 3개 결과도 공개.
- 실문서에서는 별도 CI를 제시하고, 유의하지 않으면 “실문서 개선 확인”이라고 쓰지 않기. **60건은 실행 가능한 하한이지 검정력 보장이 아닙니다.**

난이도는 dev에서 확정한 뒤 test를 봉인하세요. M1이 이기는 사례만 골라 구성하면 안 됩니다.

**3. 진행 중 작업의 유지·축소**

- **P8a 유지:** 서빙 정밀도 문제 해결은 데이터 방향과 무관한 핵심 역량입니다. 로컬 복원 확인 후 선택한 경로만 vLLM에서 검증하세요.
- **P14 유지:** BF16 M0가 강하므로 BF16 LoRA는 반드시 필요한 비교입니다. 우선 1회 확인하고 새 데이터의 주 학습 후보로 사용하세요.
- **P6 이동·축소:** 기존 쉬운 세트에서 추가 seed를 반복하는 확대 작업은 중단하고, **새 데이터에서 seed 3개와 “어려운 데이터 추가 유무” ablation**으로 옮기세요. 완료된 결과는 보존합니다([현재 계획](../../plan.md#L32)).

**4. 가장 큰 위험 두 가지**

1. **인위적인 난이도와 누수로 학습 효과를 부풀리는 것.** 읽기 불가능한 가림·축소를 피하고, 독립적인 라벨 재검수·거래 단위 분할·실문서 평가로 대응하세요. 유의한 개선은 보장되지 않으며, 실패도 유효한 결론입니다.
2. **라벨링·접근 허가 때문에 일정이 소진되는 것.** 첫날 소량으로 라벨링 시간을 측정하고 A2 범위를 확정하세요. 라이선스·출처를 확인하고 귀속 표시를 남기되, **라이선스 미확인 데이터는 평가 전용이어도 자동으로 허용되지 않습니다.** DocILE·AI Hub는 허가 확인 전 핵심 일정에 넣지 않는 편이 좋습니다.
