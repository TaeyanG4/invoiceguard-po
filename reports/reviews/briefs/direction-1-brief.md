# 의뢰: 난이도 상향 방향 자문 (독립 의견)

## 배경
- 저장소 `H:/dev/invoiceguard-po` — 채용공고(JobKorea 50342762, LLM/VLM 파인튜닝·서빙, 수출입 서류 → 통관 데이터) 포트폴리오. 현재 점수: Fable 70, astra 76. 목표는 두 평가 모두 90 이상.
- 문제: 데이터가 너무 쉽다. 같은 자체 dev 20건(깨끗한 합성 렌더)에서 **기본 모델(M0, 학습 없음) bf16 = 0.994**, NF4 = 0.941, QLoRA M1(NF4) = 0.960. 자체 test에서 M1−M0 +0.024는 유의하지 않음. 즉 파인튜닝의 가치를 보여 줄 여지가 작다. (`reports/quant/precision_dev20.md`)
- 오늘 확인한 사실: vLLM 정확도 저하 원인은 QLoRA 어댑터를 NF4가 아닌 기본 모델에 붙인 불일치(로컬 재현). 해결(역양자화+LoRA)과 bf16 위 일반 LoRA 학습을 로컬에서 진행 중.
- 사용자 방향: "어려운 난이도의 데이터를 만들거나 다른 데이터셋을 찾거나 프로젝트를 바꿔서 난이도를 올리는 방향".
- 자원: 로컬 RTX 4070 Ti SUPER 16GB(2B 모델 QLoRA 80 step ≈ 22분), RunPod 잔액 약 $9.5(승인제), 작업 기간 수일. 공개 GitHub 저장소이므로 재배포 불가 데이터는 원본·라벨 비공개, 집계 지표만 공개 가능.

## 선택지 (조합 가능)
- **A. 실데이터 추가 (프로젝트 유지)**: A1 CORD v2로 학습+평가(실사진 노이즈), A2 Kaggle 인도 세금계산서 169장 중 일부를 직접 라벨링해 실문서 스트레스 평가셋, A3 DocILE(접근 요청 후 학습·평가, 공개 baseline과 비교).
- **B. 어려운 합성 데이터 (자체 렌더러 확장)**: 촬영 왜곡(원근·그림자·흐림), 도장·손글씨 겹침, 긴 표(15–40행, 여러 줄 품명), 한영 혼합 라벨, 유럽식 숫자(1.234,56), 인보이스+패킹리스트+PO 3자 대사. 라벨 완전 통제(SKU 포함), 공개 가능.
- **C. 프로젝트 확장/전환**: 통관 서류 묶음(상업송장·포장명세서·B/L)에서 신고 필드 추출(AI Hub 71301, 직접 라벨링, 비공개 데이터).

## 답할 것 (한국어, 약 600단어 이내)
1. 추천 방향 하나(또는 조합)와 그 이유 — 공고 적합도, 파인튜닝 효과를 보여 줄 수 있는지(M0 대비 유의한 차이), 수일 안 실행 가능성, 라이선스 위험.
2. 평가 설계: 어떤 세트를 학습/평가로 쓰고 무엇을 held-out으로 고정할지, 사전에 고정할 판정 기준(예: M1−M0 유의, 실문서 세트 최소 n).
3. 지금 진행 중인 것(P6 seed·ablation, P8a 서빙 정밀도 해결, P14 bf16 LoRA) 중 방향 전환 후에도 유지할 것과 버릴 것.
4. 가장 큰 위험 2개와 대응.
