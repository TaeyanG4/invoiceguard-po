# 00. 프로젝트 기획 — InvoiceGuard-PO v3

## 한 문장 목적
**가상 부품 수입 담당자가 영어 인보이스의 품번·수량·단가를 발주서와 비교할 때, AI가 입력 초안과 확인할 차이를 먼저 만들고 사람이 원문을 확인한 버전만 내보내는 검수 지원 도구.**

가상 회사 '한빛부품무역'를 시나리오로 사용한다. 실제 회사의 내부 업무나 요구사항을 조사한 결과는 아니다. 발주 100개×USD 2.50, 송장 100개×USD 2.75일 때 정상적으로 2.75를 추출해 단가 차이를 알리는 것이 성공이다. 원문을 PO의 2.50으로 고치는 것은 실패다. 실제 거래 변경인지 AI 오독인지는 원문·사람 검수/평가 정답 없이는 단정하지 않는다.

## MVP 경계
- 입력: 영어 한 페이지 PNG/JPEG, 독립 PO JSON, USD/EA, 2–6개 품목을 중심으로 한 데모.
- 처리: 실제 VLM → 보수적 파싱 → SKU 정확 매칭 → 차이 목록 → 수정/확인 → 승인한 현재 버전 JSON/CSV.
- PDF, 다중 페이지, 부분선적 정산, 실제 지급/통관, HS코드, 챗봇, RAG, 다중 사용자, bbox 생성은 이번 범위 밖.
- 일치 후보여도 사람 승인 필요. 전체 업무시간 절감, 실제 기업 정확도, 오지급 예방액은 측정 전 주장하지 않는다.

## 데이터의 한계
공개 InvoiceOCR-Synth와 자체 생성 Invoice–PO는 **모두 합성 데이터**다. 전자는 이미 존재하는 공개 데이터라는 뜻이지 실제 기업 거래를 수집한 자료라는 뜻이 아니다. 공개 주석에는 품목별 SKU가 없으므로 SKU 평가는 자체 데이터에서만 한다. 외부 실거래 데이터 검증은 P1이다. [S01]

## v3 변경 핵심
숫자 라벨을 원문 문자열 정답으로 쓰던 모순을 제거했다. 공개 자료는 canonical 수치 추출, 자체 렌더 문서는 raw 전사로 나누고 한 모델에 서로 다른 고정 프롬프트를 사용한다. 계획 규모는 standard/mini 두 개만 두고 훈련용 파일럿 이후, 평가 전에 하나를 동결한다. 가격은 콘솔 견적을 입력받으며 GPU 예산 $7+보관/종료 여유 $1+잔액 유보 $2로 나눈다.

## 현재 상태
기획·설계·계약·예제 검사는 실행했지만 전체 데이터 다운로드, 실제 학습, GPU API, 제품 구현은 하지 않았다. 이 패키지는 런타임 완료 증명서가 아니다.
