# 02. 제품 요구사항·완료 조건

## 제품 범위

로컬 단일 사용자용 포트폴리오 프로토타입. **완전 자동 통관/지급 시스템이 아니라 입력 초안과 차이 검수 지원 도구**다. 모든 제품 내보내기는 사람 승인 이후만 가능하다.

## P0 요구사항

| ID | 요구사항 | 검증할 동작 |
|---|---|---|
| R01 | 독립된 PO 등록 | JSON 계약 검증, SKU 앞자리 0 유지, 중복 SKU 차단 |
| R02 | 이미지 입력 | PNG/JPEG 내용 검증, 10MB/20MP 초과 차단, 로컬 경로 노출 금지 |
| R03 | 모델 추출 | 이미지+고정 prompt만 입력, 실제 모델 식별자와 원문 응답 기록 |
| R04 | 구조 검증 | malformed JSON/출력 잘림은 명시적 실패, 빈 값 임의 생성 금지 |
| R05 | 보수적 정규화 | raw 보존, USD/EA 지원 범위만 Decimal 변환 |
| R06 | PO 대사 | SKU 정확 매칭, 수량·단가 차이, 미등록·누락 SKU, 단위/통화 불일치 |
| R07 | 검수 화면 | 원문 전체+읽은 값+PO 값+차이 사유를 나란히 제시 |
| R08 | 수정·승인 | 수정 이유와 version 기록, 현재 버전만 승인 가능 |
| R09 | 승인 후 내보내기 | 승인 없는 요청 409, 수정 뒤 이전 승인 무효 |
| R10 | 실제 파인튜닝 | 실제 adapter와 로그, 학습된 파라미터 범위 확인 |
| R11 | 평가·회귀 | 영어 공개 InvoiceOCR-Synth / 자체 영어 합성 PO 별도 지표, 예측 원본/분모/실패 포함 |
| R12 | 오류 개선 | dev 실패 최대 10건(더 적으면 실제 실패 전수와 부족 사유) 분류, 한 가지 개선과 회귀 사례 추가 |
| R13 | GPU 서빙 | 실제 추론 API, latency/throughput/VRAM 측정 |
| R14 | 재현성 | 환경·revision·데이터 manifest·실행 command 기록 |
| R15 | 비정상 입력 안전 처리 | 문서의 지시문을 실행하지 않고 텍스트로 취급 |
| R16 | 상태 구분 | fixture/mock/cached replay/live 상태를 분명히 표시 |

`R10` 또는 `R13`이 GPU 미확보로 막히면 기능 데모만 완료한 것이다. 다섯 직무 역량 전체를 입증했다고 표시하지 않는다.

## P1 — 남는 예산에서만

CSV PO import, 이미지 회전 보정, 단일 페이지 PDF, 4-bit 서빙 비교, 더 큰 학습셋, 원문 위치 하이라이트. P0의 학습/평가/증거를 빼고 P1을 먼저 만들지 않는다. CSV export는 P0이고, JSON PO import가 P0이므로 CSV import가 없어도 전체 흐름을 시연할 수 있다.

## 비기능 요구사항

- 로컬 loopback에서만 기본 실행한다. 인증 없는 공개 서비스로 배포하지 않는다.
- 학습과 서빙은 하나의 GPU에서 동시에 실행하지 않는다.
- 모델 응답을 기다리는 동안 실패/진행 상태를 구분한다. 타임아웃 120초는 사용자 경험을 위한 상한이지 성능 목표가 아니다.
- GPU 메모리와 지연은 실제 장비에서 측정하며, 이 문서의 예상 사양을 측정값으로 제시하지 않는다.
- 승인/수정은 SQLite transaction+버전 비교로 처리한다.
- 모델 없는 상태에서 샘플 정답으로 자동 대체하는 silent fallback은 금지한다.

## 완료 수준

### A. 기능 데모

직접 만든 fixture로 upload→review→approve→export가 작동하고 CPU 테스트가 통과한다. 모델 역량을 증명하지 않는다.

### B. 직무 대응 최소 완성본 — 이번 목표

A에 더하여 공개 영어 InvoiceOCR-Synth 실제 이미지 적재, 합성 이미지 생성, 실제 모델 baseline, 실제 QLoRA 1회, 비교 지표, 오류 분석/개선 1회, 실제 GPU API benchmark가 존재한다. 모든 결과에는 데이터 성격과 한계가 표시된다.

### C. 현장 검증 제품 — 이번 범위 밖

사용 허가를 받은 실제 상업송장/PO, 다양한 통화/단위, 사용자 효과 검증, 보안 및 다중 사용자 기능, 운영 모니터링이 추가로 필요하다.
